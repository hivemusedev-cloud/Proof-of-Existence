# poe-node

The Proof of Existence blockchain node, built in Rust against the verified
Lean specification (`Proof_of_Existence_v1_1_1_CC.lean`).

**Public testnet `poe-testnet-1` is live** (Step 12c, launched 2026-11-13):
see [`testnet/TESTNET.md`](testnet/TESTNET.md) for how to join and
[`testnet/BOUNTIES.md`](testnet/BOUNTIES.md) for the three falsifier
bounties (F-Height, F-Clone, F-First-Year).

## Increment 1 — poe-kernel (this build)

A definition-for-definition port of the Lean kernel's core:

- `crates/poe-kernel/src/lib.rs` — claims (`Spend`), settlement (`settle`,
  `register`, `first_tx`, `evidence`), multi-height settlement (`settleM`),
  the money constants and grant law (`pot`, `grant`, `emission`), and a
  stateful `Registry` over the kernel's ten registry kinds.
- `crates/poe-kernel/src/ledger.rs` — notes, assets, the five acts
  (`Op::Join / Create / Issue / Transfer / Tick`), validity predicates, and
  the genesis ledger, mirroring the Lean `Ledger`/`act`/`runOps`.
- `crates/poe-kernel/tests/kernel_batteries.rs` — acceptance batteries
  modelled on the Fortran twin's T1/T2 streams and on the Lean theorems
  (`settle_nodup`, `settle_canonical`, `merge_registers_the_union`,
  `evidence_is_complete`, cap and window rules).
- `crates/poe-node` — a small demo binary: genesis → join → close → spend →
  double-spend refused.

Deliberate porting choices: std-only (no dependencies in the kernel); Lean
`Nat` becomes `u64` (heights/ids) and `u128` (value sums); Lean's division
by zero = 0 is preserved in `pot_share`.

## Increment 3 — crypto carriers (Step 2, done 2026-11-13)

`crates/poe-crypto` (10/10 tests):

- `hash` — `H`, byte-for-byte the Compute Seed's construction: SHAKE256
  under `b"PoE/" + tag`, length-framed parts, naturals in 64-byte
  big-endian, 512-bit output. Test vectors generated by the Python original
  match exactly. Merkle commitments ported with the seed's odd-node-carried-up
  rule and empty-root constant.
- `tickets` — hash-chain proposal tickets: commit the tip, reveal one link
  per round, hashing forward verifies; win below `16/A` of the range.
  Boundary test is exact (the reference ticket wins at A=25, loses at 26);
  a 4,000-reveal census at A=200 lands near the expected ~320 winners.
- `xmss` — one-time vote keys: WOTS+ leaves (w=16) under a Merkle tree.
  The state discipline is the deliverable: an index is reserved and the
  state file persisted (write + fsync + atomic rename) *before* any
  signature is produced, so a crash burns a leaf but can never reuse one —
  covered by a crash-simulation test. Single-tree member of the family;
  the manual's 2^40-leaf multi-tree layering + production audit are Step 5
  hardening, stated in the module docs.
- `pq` — ML-DSA-87 (signatures, 4,627-byte sigs) and ML-KEM-1024 (messaging
  key establishment) as thin wrappers over the audited `fips204`/`fips203`
  crates; no cryptography implemented in-house. SLH-DSA not wired — ML-DSA
  covers the signature carrier; SLH-DSA stays a named alternative.

## Increment 4 — storage (Step 3, done 2026-11-13)

`crates/poe-store` (5/5 tests), plus kernel additions `Ledger::pruned`
(the Lean `pruneL`, ported), `Ledger::accepts` / `is_input_ok`, and
`Registry::restore`:

- Canonical encoding (fixed-width big-endian) for notes, acts, ledgers,
  spends — identical bytes on every machine.
- Append-only act log (length-framed, checksum per record) + atomic
  snapshots; replay on open rebuilds the ledger, and a torn tail from a
  crash mid-write is detected and dropped, never applied (tested).
- Per-epoch **state roots**: at each close, `H("state-root", …)` chaining
  the previous root, epoch, minted, live coin, a running births
  accumulator, and set sizes. Pruning never touches the root chain, so
  pruned and full nodes with the same history hold the same roots.
- Pruning verdict battery (T16 mirror at battery scale): a history run
  530 epochs — past the 522 window — then 10 candidate acts (replayed
  join, fresh join, renewals, creates, issues at/over the kept remainder,
  burned and dead inputs) whose verdicts agree between full and pruned,
  plus the input-verdict statement of `the_window_is_enough` itself.
  Scoping, stated in the test: candidates use genuinely fresh marks, as
  honest acts do; reusing a *forgotten* mark is the one case pruning
  cannot see, by design.
- Cuckoo filter over window nullifiers: no false negatives (10,000/10,000
  found), false positives under the 1% bound — an index only; verdicts
  always confirm against the exact death set.
- Backend note: the store is the workspace's own log+snapshot format
  behind the `Store` API. The API is the contract; a RocksDB backend can
  replace the files behind it later without touching callers (its C++
  build is deliberately not pulled into this workspace yet).

## Increment 5 — ordering + finality + networking (Step 4, done 2026-11-13)

Built exactly as BUILD_FLOW Step 4 specifies — three new crates:

- `crates/poe-dag` (3/3 tests) — BlockDAG assembly and **GHOSTDAG
  linearization implemented from the PHANTOM/GHOSTDAG spec**: selected
  parent by blue score, mergeset considered in decreasing blue-score
  order, a candidate is blue iff at most `k` current blues sit in its
  anticone. Content-addressed blocks (`H("block", …)`), so the total
  order is a pure function of the block set — the battery proves two
  DAGs fed the same 60 blocks in different valid orders produce the
  identical linearization and identical blue scores. This replaces the
  manual's imported ordering assumption with tested code.
- `crates/poe-finality` (2/2 tests) — round beacons (`H` over a
  finalized reference block, domain-separated — see the live-network
  corrections under Step 12c below); proposal draws verified against the
  committed ticket chain under the manual's 16/A rule; committees
  sampled by tickets (target 32); XMSS one-time votes with leaf-reuse
  rejection; **>2/3 finality**; double-proposals and equivocations
  become evidence under the kernel's one law (per-machine Proposal/Vote
  registries) and revoke their author; heartbeat signing (ML-DSA) plus
  the crediting rule (credited iff every owed vote was cast).
  **The finish-line simnet passes**: 10 machines, 3 Byzantine (two
  double-propose, one equivocates), 24 rounds, votes delivered 2 rounds
  late — all 24 rounds finalize exactly one block, every Byzantine act
  yields evidence + revocation, honest machines are heartbeat-credited
  in all 3 epochs, and two instances with different insertion orders
  agree on the linearization and the finalized set.
- `crates/poe-net` (1/1 test) — **libp2p gossipsub** as the flow names:
  topics `poe/blocks`, `poe/votes`, `poe/acts`, content-hash message
  ids (dedup), mDNS + direct dial. Two nodes on localhost exchange
  block and vote payloads in the integration test. (The unadopted
  transport proposal document is a different design and is not what
  this crate implements — noted in the crate docs.)

Simnet runtime note: the finality battery takes ~3 minutes in a debug
build on this VM (XMSS/ML-DSA in debug profile), all of it crypto, none
of it waiting.

### Live-network corrections (found by running it, 2026-11-13)

The lockstep simnet passed from the start; the live network did not
converge until four network-facing readings were corrected. The
kernel and money rules are untouched; each correction is also
documented at its code site.

1. **Beacon anchor.** Round beacons hashed the node's *current
   selected tip*, which changes with every block a node happens to
   have received — two honest nodes sampled different committees and
   refused each other's proposals. Beacons now hash the *finalized
   block of the round two back* (the genesis block for rounds 0–1): a
   fixed point every honest node holds identically.
2. **Reveals are buffered, not dropped.** A ticket reveal that
   arrived before its machine's registration had landed was refused
   and lost; that node's committee for the round silently shrank
   (in the worst case to itself, finalizing its own block). Reveals
   are now held until registration lands, and gossip messages carry a
   nonce so republication is not suppressed by content-hash dedup.
3. **Rounds are never skipped.** The round loop took its round from
   the wall clock; a node whose pre-genesis wait overshot genesis by
   one round never closed round 0's committee and never cast its
   vote, stalling the chain one vote short of finality forever.
   Rounds are now processed strictly in sequence; a node behind the
   clock replays its missed rounds back-to-back.
4. **Heartbeats sign after finality.** The epoch heartbeat commits
   to the finalized tip of the epoch's last round, but was signed at
   the boundary round — one round before that tip was final — over
   the zero tip no verifier accepts. Heartbeats are now signed in
   the first round where the epoch's last round is final, and closes
   wait one further round so peer heartbeats can arrive.
5. **Bundle joiners catch up over gossip; restarts resume.** The
   first live late joiner stalled permanently: its bundle ended at
   an epoch boundary, the votes for the rounds since had been cast
   before it came online, and gossip has no memory. Nodes now retain
   accepted votes and reveals for a bounded window and re-serve the
   current epoch's history when a new machine registers, so a joiner
   finalizes the gap in-protocol. And a restarted node restores from
   the bundle in its own data directory, rejoining at the frontier
   with its pre-restart rounds marked missed — re-claiming a round
   it already proposed or voted in could be evidence against itself.
6. **Windows fsync needs a writable handle** (found on a Windows
   run, 2026-11-13). XMSS persistence re-opened its temp file
   read-only to fsync it; Windows refuses to flush a read-only
   handle (`PermissionDenied`), so no vote key ever persisted
   there. The same pattern in the store's snapshot and registry
   writes is fixed the same way.

### Live-network corrections, second night (2026-11-14)

Running the third genesis for hours, under restarts and churn,
found the next layer — all in the network-facing node, none in the
kernel or money rules:

7. **Full finality snapshots.** Bundle-only resume rewound a
   restarted node to the last epoch close and re-marked everything
   since as missed; worse, a node killed mid-epoch resumed into a
   stall (its votes for the current epoch existed only in memory).
   Nodes now persist their complete finality state after every
   round (`finstate.bin`: committees, reveals, vote store, claims
   above a floor at the last finalized epoch) and resume from their
   exact position, re-casting their own votes for unfinalized
   rounds — the registry makes peers treat them as duplicates,
   never as second claims.
8. **Catch-up dwells.** A bundle joiner raced through its gap
   rounds in milliseconds and closed their committees before peer
   history arrived — finalizing a solo view an epoch long. A
   catching-up node now waits, briefly and boundedly, for peer
   reveals and blocks for a past round before closing its committee
   or voting in it.
9. **History retention 2 → 16 epochs**, and announcements now carry
   the announcer's live position (`sync_hint`), so a joiner asks
   for — and the network re-serves — the rounds that actually lead
   to the frontier.
10. **Canonical-proposal guard.** A sequentially resumed node
    re-processed rounds it had proposed in before the kill and
    minted *second, different* blocks for them — manufacturing
    equivocation evidence against itself and its peers. A node
    that already holds a canonical proposal for a round re-serves
    it and never mints another.
11. **Orphaned-join retry.** The join marker cleared only when the
    join landed in the ledger; a join proposed in a block that
    never finalized was therefore never proposed again — a late
    joiner could wait forever, silently. Once the proposing round
    is final without the join, the marker clears and a later round
    re-proposes. (Proven live: epoch 76, `claimants=1`.)
12. **Mesh hygiene under load.** Three scale bugs in one: votes
    re-served by history were fully re-verified (XMSS) even when
    already recorded — a duplicate fast path now answers first,
    and vote() closes a round's committee on demand when its
    beacon anchor is already final; the periodic peer re-dial
    opened a *new* connection every time (160 connections among 4
    nodes, starving the hub) — dialing now skips connected peers;
    and history was re-served as the whole retained range every
    round — it is now walked in slices.

**Liveness under churn — mechanism adopted and implemented
(2026-11-15, correction 23).** The finding stood as follows: a
round whose drawn committee loses a vote (a voter crashes, lags
an epoch, or votes a different block after late delivery) could
sit one vote short of finality forever: committees are drawn
once, votes are one-time claims, and finality is sequential.
The chain stalled this way at rounds 752, 1084, 1231 and 1528,
and recovery was an operator re-anchor from the last epoch
bundle. The owner adopted the skip-attestation design on
2026-11-15 — the next round's committee witnesses the empty
round, and at >2/3 attestation it finalizes as a null round —
specified and proved in the Lean extension before the Rust
landed (corrections 23–24). The operator re-anchor remains the
fallback for stalls the attestation cannot witness (e.g. the
attesting round itself never forms). The full account is in
`testnet/TESTNET.md` (operations log).

Acceptance evidence: genesis of 2026-11-13 21:14 +06 — three nodes
over real libp2p finalized in lockstep with identical closes
(epoch 0: 3 claimants × 100,000, credited 3, root
`101456563fc6902d`). Current chain (third genesis, 2026-11-14
00:30 +06): epochs 0–66 identical on three nodes; a mid-epoch
restart resumed from finstate and kept closing identically; at
epoch 76 a late joiner's join landed on independent nodes with
root `d68cda776b23a5c9` (`claimants=1, grant_each=99999`). Full
workspace suite after all corrections: **67/67 tests pass**
(2026-11-14). A note on zero-claimant epochs: that is the kernel's
own law, not a stall — `Join` is once-ever per machine and later
claims come from new joins and from renewals after 25 faithful
epochs.

The first genesis (20:52 +06) ran for nine minutes before the
late-joiner gap in correction 5 was found; the chain was reset
before any external participation. Two further geneses and four
clock re-anchors followed on 2026-11-14, all before external
participation — and none could have had any: the operator's VM
has no inbound reachability (see `testnet/TESTNET.md`). The
chain's current position and bootstrap identities are kept
current in `testnet/TESTNET.md`, not here.

### Live-network corrections, third round — the issue #1 fixes (2026-11-14)

The first external tester (issue #1) and a scale simnet found the
next layer. All fixes are in the node/finality implementation; the
kernel and money rules are again untouched:

13. **Hold, never solo-close.** The catch-up dwell (correction 8)
    waited a bounded 2.5 s for peer material and then closed the
    round anyway — on a reveal set containing only the node
    itself, which samples itself as committee and finalizes a
    private fork (the tester's epoch 114 diverged from canonical
    exactly at his own join). A round with no peer material is now
    HELD — pumped, logged, never closed — on the catch-up path and
    on the live path alike. A node that cannot see peers stalls;
    it does not fork.
14. **The resume wedge.** A node resuming from `finstate.bin`
    pre-marked every round up to its apply point as already
    voted — including the first unfinalized round, whose vote is
    only cast in the *next* round's processing. The resumed node
    therefore never cast that vote, and the round sat one vote
    short forever whenever the vote was quorum-critical
    (reproduced at rounds 1837, 1853, 1872, 1874). Only finalized
    rounds are pre-marked now, and every cast vote is persisted in
    the same round it is cast, so a resume re-casts the identical
    claim (a duplicate everywhere), never a different one. The
    finstate format is versioned (POEFIN2); an unreadable finstate
    degrades to the epoch bundle instead of bricking the node.
15. **Iterative GHOSTDAG ordering.** The ordering walk recursed
    over the selected-parent chain; its depth grows with retained
    history, and it overflowed a Windows node's 1 MB main-thread
    stack mid-replay (issue #1, finding 2). The walk is iterative
    now, proven order-equivalent to the recursion by a property
    test over random DAGs, plus a 4,000-deep chain ordered on a
    256 KB stack as a regression test.
16. **Frozen draw denominators.** Committee and proposer ticket
    draws divided by the *live* count of active machines — a
    number that changes as revocations land, so two nodes holding
    the same blocks could disagree about whether a proposal was
    legitimate and build different DAGs. Invisible at 10 machines
    (target ≥ active: the draw always wins); exposed by the new
    100-machine simnet, whose two insertion orders diverged. Each
    round's denominator is now frozen at its reveal close, from
    its own participant set, and carried in the finstate.
17. **Catch-up pace.** History serving walked 16 rounds per
    server round; a deep joiner's pace was slice-bound at ~5
    rounds/min against a 20 rounds/min wall clock, so its backlog
    *grew*. Slices are 64 rounds now (see SERVE_SLICE_ROUNDS),
    putting a deep replay comfortably ahead of the wall.
18. **The anchor round (found at the redeploy).** A bundle-synced
    node observes its anchor round — it "missed" the collection.
    After an operator re-anchor (t0 shifted), that is wrong: the
    round's window moved with t0 and *nobody* collected it, so
    every synced node sat the round out and the chain held at the
    anchor forever. If the dwell for an observed round expires
    with no peer material anywhere, the node now contributes its
    own reveal late and plays the round (the hold still applies —
    it closes only once a peer's material joins), with a short
    settle so slower peers' late reveals land before the close.
19. **Serve-behind, and dwell on resume (found at the redeploy).**
    History re-serving is push-only, and a finstate-resumed node's
    serve window stayed shut — so a reveal or vote lost in a
    mesh-formation race was never re-served: the owner raced on,
    the loser held forever (an anchor deadlock). A node now
    extends its serve window whenever a peer's announced position
    is behind its own, starts the serve range at that peer's
    position (known machines included, not just new
    registrations), and resumed nodes take the same catch-up
    dwell as synced ones on rounds they have not finalized.
20. **Buffered reveals starved the holds (found at the redeploy).**
    Inbound reveals are buffered until their machine registers,
    and the buffer was flushed only at fixed points in the round
    loop — never inside the pump that every wait uses. Two nodes
    holding the same round for each other's reveals therefore
    deadlocked with the material already in their buffers. The
    pump now flushes after every poll, re-publishes the node's
    own reveal for a held round (with a fresh nonce, or gossip
    suppresses the repeat), and re-dials configured peers every
    ~20 s — a peer connection dropped during a hold (or a peer
    that was redeploying at startup) no longer isolates a held
    node forever.
21. **Entrypoint checkpoint shadowing (found at the redeploy).**
    The Railway entrypoint fetched a new anchor bundle and wiped
    the chain state, but left the node's own stale `bundle.bin`
    checkpoint in place; when the container recycled mid-boot,
    the second start plain-started and its fallback synced from
    the stale checkpoint — a *fork* bundle (epoch 162) — instead
    of the anchor it had just fetched (epoch 209). The fetched
    bundle is now installed as the node's own checkpoint too.
22. **Bounded DAG representation (the open finding below, fixed
    2026-11-15).** `poe-dag` no longer stores a full ancestor set
    per block. Each block keeps an exact ancestor oracle — its
    ancestors inside a 32-round window plus a frontier cut set —
    which answers `is_ancestor` identically to the full set for
    any window size, and its GHOSTDAG blues/reds as a rope over
    the chosen-parent link, materialized on demand instead of
    cloned per block. Stored reds are dropped (they were
    write-only in production). Gate: a differential battery
    against a verbatim copy of the previous implementation
    (random DAGs at k = 0..3 with all-pairs ancestry checks, a
    6-wide × 300-round mesh, a 2,000-block chain) — linearization,
    blue scores, ghost data, and tip selection identical. Shaped
    replay probes (release, this VM class): 3,595 blocks —
    checksum identical, peak RSS 72 MB vs the old code's
    1,696 MB; 11,991 blocks at the testnet's width — 419 MB (the
    old curve is quadratic and does not run at that size here).
    Memory is now linear in chain length. Honest caveat: replay
    *time* keeps the old asymptotics (each insert materializes
    the chosen parent's blues) and the oracle is ~1.6× slower per
    block at 3.6k blocks; from-genesis replay is a from-scratch
    catch-up cost only — nodes resume from finstate or a bundle.
23. **Skip attestation — the liveness mechanism (owner-adopted
    2026-11-15; specified in the Lean extension
    `PoE_SkipAttestation.lean`, proved against the kernel's
    Part B finality).** When a round is still unfinalized at the
    next round's vote, that vote may carry a second XMSS
    signature over a domain-separated `skip_message(round-1)`.
    At more than two thirds of the attesting round's committee,
    the stalled round finalizes as a null round (`NULL_BLOCK`:
    no acts, no votes credited, nothing minted — grants are an
    epoch-close function over finalized rounds and the null side
    is not a DAG block). Block finality, once reached, is never
    overridden by attestations; the Lean proof shows the two
    outcomes can coexist only by naming more than a third of
    validators in both supports. Finstate format bumped to
    `POEFIN3` (adds the attestation tallies; older formats
    degrade to the bundle resume as before). Battery
    (`simnet_skip`): lost votes close as a null round and the
    chain advances; attestations never override a block quorum.
24. **Late attestations are inert (found by the battery above).**
    An attestation counted only after its round already
    finalized is neither tallied nor recorded — exactly like a
    late vote. Without this, the conflict query named honest
    machines as double actors (an attestation is cast against a
    lagging local record and counted later). `skip_conflicts`
    now reads only attestations that were live when counted,
    and a hand-driven test names exactly the one machine that
    attested a round empty while it was open and also voted for
    the block that round finalized with.
25. **Epoch compaction (2026-11-16).** At every epoch close the
    node now tries to drop the finalized history below the
    closed epoch's first round, so retained DAG memory tracks
    the live window instead of the whole chain. `Dag::prune`
    drops only strict ancestors of an anchor block, and only
    when the anchor is an ancestor of every current tip (the
    pruning point); while a long-lived fork's tip does not
    descend from the anchor, pruning refuses and drops nothing
    — the next epoch's close retries. References from retained
    blocks into the dropped set are discharged, never left
    dangling: mergeset/colour references protect their targets
    (reference closure), a cut chosen link materializes its
    pre-drop blues/reds into the survivor's stored base lists
    (so `ghost()` answers stay byte-identical), and parent
    links are discharged into seed maps — the round, parents,
    and window/frontier oracle of every pruned block that a
    survivor still names — so `is_ancestor` keeps answering for
    pruned ids exactly. Snapshots carry the full retained state
    including the seeds (`Dag::export_state`/`from_state`, no
    re-insertion): bundle format `POEBNDL2` (v1 bundles stay
    readable) and finstate `POEFIN4` (older finstates degrade
    to the bundle resume, as before). The blocks-only restore
    path demonstrably cannot do this — a pruned parent makes
    re-insertion drop the anchor and its whole descendant cone —
    and a poe-finality test pins both halves of that statement.
    Gate (`crates/poe-dag/tests/compaction.rs`): a fork-heavy
    mesh (long-lived fork diverging at round 20, merging at 70)
    run in lockstep, compacting at every epoch boundary vs
    never compacting — selected tip, tip sets, per-block blue
    scores, ghost blues/reds/mergeset order, all-pairs ancestry
    over every block ever inserted, vote targets, post-prune
    inserts, and an export/restore round trip all identical.
    The gate caught two real bugs on the way in, both fixed:
    the seed-closure scan missed oracles from earlier prunes,
    and insert's window filter classified pruned ids by the new
    block's round instead of their own. Also landed with this
    correction: poe-zk's fold seed is now anchored to the
    node's `H` (`anchored_seed` / `verify_anchored` in
    poe-zk) — a proof made for one kernel object no longer
    verifies for another. The fold itself stays algebraic; an
    in-circuit Poseidon2 accumulator remains deliberately
    unbuilt ahead of the external ZK review (see the poe-zk
    crate docs).
26. **Two-caps — CLOSED by the owners' Option A (2026-11-17).**
    The Step 10 composition proof's design gap (see the Residue
    section's earlier account) is closed on the owners'
    decision: machine closes hand the lesser of the two caps,
    `min (vcap) (kernelCap)`. In the Lean composition workspace
    the liquidity machine's `Sys.close` now hands
    `min (vcap …) (kernelCap false …)` — the `false` reading,
    which bounds both v1 readings — and the tokenomics
    envelope, including the first-year grant bound of
    520,200,000,000, is now proved **unconditionally**
    (`the_composition_envelope`, `the_composition_first_year`);
    the audited Kernel and Tokenomics files are byte-identical
    to the originals, and the pre-amendment composition is
    preserved in the build tree. The oracle-cap envelope is
    not pursued. In Rust the close path never handed an oracle
    cap — `poe_epoch::close` hands `cap_p`, whose module part
    `mod_cap` is the kernelCap analogue — and a battery now
    pins that for every profile and operating point:
    `cap_p ≤ mod_cap` and `cap_p ≤ 100,000`, and 0 when no
    machine is registered.
27. **Finality certificates (2026-11-17, light-duty design
    note §4, built on the owners' approval).** At each epoch
    close the node now emits a portable certificate
    (`poe_finality::cert`, wire format `POECERT1`): the epoch's
    state-root chain link, minted total, the Merkle companion
    root (correction 28), the root-signed announcements, the
    close round's reveals, and the committee's XMSS votes for
    the close block. Verification is evidence-only — a light
    client re-derives the committee from the reveals exactly
    as the finality engine does (frozen draw denominator,
    correction 16) and counts the votes itself; it trusts no
    emitter assertion except the `revoked` set, which is
    monotone across the chain and cross-checkable between
    sources. The Lean statement of the verification's
    soundness (`PoE_Certificates.lean`) reduces to the kernel's
    Part B quorum intersection, like skip attestation.
    Boundaries, stated in the module docs: an epoch closed by
    skip attestation (null close) has no certificate in this
    shape, and no certificate has been emitted on the live
    testnet yet — node1 holds at the epoch-209 anchor without
    a canonical mesh, so emission is proved in the simnet
    battery (two epochs certify and chain-verify; a tamper
    battery refuses each mutation for its stated reason), not
    yet live-observed. Certificates are served locally over
    the control surface (`cert.latest`, `cert.fetch`).
28. **Merkle companion root (2026-11-17, light-duty design
    note §6).** The chained state root yields no per-note
    path, so `poe_store::merkle` now builds a companion root
    over three sorted sections of the ledger — births (live
    notes, keyed by commitment), deaths (spent nullifiers),
    and machines — each a sorted Merkle tree whose structure
    proves both inclusion and, by neighbouring leaves,
    absence. A note is proved live by a births inclusion path
    for its commitment plus a deaths absence path for its
    nullifier; a spent nullifier is proved by a deaths
    inclusion path. The companion root is computed at each
    epoch close, named in that epoch's certificate
    (correction 27), and proofs for the close-time ledger are
    served over the control surface (`note.proof`). Battery:
    genesis determinism, a spend moving a note from births to
    deaths (its old proof then fails), tamper refusal, and
    absence/inclusion at every edge of a populated ledger.

    at that width. `poe-wallet::detect` implements it

30. **Windows control pipe hardening** (2026-11-17, from
    the owner's first real-Windows run of the shell). The
    node ran correctly — fresh identity, canonical bundle
    state, HOLDing its round instead of solo-closing — but
    the shell never reached its control pipe (`connect
    ENOENT` on every call while the node log already showed
    the pipe listening). Two weaknesses, both fixed: the
    node's pipe server treated a failed `CreateNamedPipeW`
    as fatal to the control thread — so one name collision
    (e.g. a leftover `poe-node.exe` from an earlier launch
    still holding the pipe name, `ERROR_PIPE_BUSY`) silently
    removed the surface for the process's whole life while
    the node ran on; creation now retries (throttled log)
    and takes over when the holder exits, and the listening
    line prints only once an instance exists. And the
    shell's control client made a single connection attempt
    per call, so any transient pipe error became a standing
    "unreachable"; it now retries transient failures
    (ENOENT/EPIPE/ECONNRESET/ECONNREFUSED/timeout) with a
    short backoff inside the call's deadline. Verified
    under Wine: a second node started against a held pipe
    name logged the busy retry, took the pipe over when the
    holder was killed, and answered `status` immediately.
    Shell version 0.1.1 carries both fixes.
